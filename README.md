# Autonomous Document Agent (FastAPI + free LLM)

A Python API that accepts a natural-language request, **creates its own TODO plan**,
executes each step, and returns a **polished Microsoft Word (.docx)** business document.
Built for the "Python AI Engineer - Autonomous Agents" 60-minute build challenge.

## What it does

`POST /agent` with `{"request": "..."}` -> the agent:

1. **Plans autonomously** - asks the LLM for a JSON plan (doc type, title, assumptions,
   ordered tasks, sections). Never asks the user questions; ambiguities become recorded
   assumptions.
2. **Validates the plan** - tolerant JSON extraction + schema check, one retry, then a
   deterministic fallback plan so a bad LLM reply never dead-ends a run.
3. **Executes the tasks** - analyze -> outline -> draft each section -> review
   (minimum-substance check) -> export.
4. **Exports a styled .docx** - title page block, assumptions list, headed sections, footer.
5. **Returns the full trace** - plan, assumptions, timestamped execution steps, provider used,
   and a download URL for the document.

## Mandatory engineering improvement: Retry & Fallback logic

Chosen improvement: **Retry & fallback logic** (from the allowed list).

- **What:** `app/llm.py` `LLMClient` chains four providers - Groq -> Gemini -> Ollama ->
  deterministic offline mock. Each provider call is retried with exponential backoff and
  jitter; on repeated failure the next provider takes over. Separately, `app/planner.py`
  retries *invalid LLM output* once and then falls back to a built-in plan.
- **Why:** free-tier LLMs are the least reliable part of the system (rate limits, timeouts,
  malformed JSON). A build challenge graded on a live demo must not fail because one
  provider hiccuped.
- **How it helps:** the agent degrades gracefully - a slow/dead/misbehaving LLM changes the
  provider name in the response, not the outcome. Every attempt is recorded in
  `LLMClient.attempts` for observability, and tests prove both recovery paths.

## Free LLM options (no paid credits)

| Provider | Setup | Notes |
|---|---|---|
| Groq (default) | `export GROQ_API_KEY=...` from https://console.groq.com | Free tier, fast, llama-3.3-70b |
| Gemini | `export GEMINI_API_KEY=...` from https://aistudio.google.com | Free tier, gemini-2.0-flash |
| Ollama | `ollama pull llama3.2` + server on localhost:11434 | Fully local, no key |
| Mock fallback | nothing (or `AGENT_LLM=mock`) | Deterministic offline stand-in so the pipeline always runs; clearly labelled in responses |

## Quickstart

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export GROQ_API_KEY=...        # or GEMINI_API_KEY, or run Ollama, or skip for mock mode
uvicorn app.main:app --reload
```

```bash
curl -X POST http://127.0.0.1:8000/agent \
  -H 'Content-Type: application/json' \
  -d '{"request": "Create a project plan for migrating our internal wiki to a new platform over 6 weeks."}'
```

Response includes `plan`, `assumptions`, `steps`, and `download_url` (`GET /download/{id}`).

## Demo + tests

```bash
python demo.py        # runs BOTH required test inputs end-to-end, prints plan + trace
pytest tests -q       # 6 tests, all offline
```

Test inputs used (in `demo.py` and `tests/`):

- **Standard:** "Create a project plan for migrating our internal company wiki to a new
  platform over 6 weeks."
- **Complex/ambiguous:** "Prepare something for the board about the Q3 product thing - we
  may need budget numbers but Finance has not confirmed them, keep it short but make sure
  it covers everything, and we might present it Tuesday or maybe next month."
  -> the agent records assumptions (unconfirmed budget, board audience, mock dates) instead
  of stalling, and still delivers a complete document.

Sample outputs generated by real runs: `outputs/sample1_standard_project_plan.docx`,
`outputs/sample2_complex_board_update.docx`.

## Project layout

```
app/main.py      FastAPI app: POST /agent, GET /download/{id}, GET /health
app/agent.py     Orchestrator: plan -> execute tasks -> review -> export, with step trace
app/planner.py   LLM plan prompt, tolerant JSON extraction, schema validation, fallback plan
app/llm.py       Provider chain + retry/backoff/fallback (the mandatory improvement)
app/docgen.py    python-docx rendering (title block, assumptions, sections, footer)
demo.py          Runs both required test inputs and prints the full trace
tests/           6 offline tests incl. malformed-JSON recovery and fallback-plan path
```

## Honest limitations

- Verified end-to-end against the offline mock provider and the FastAPI test client; the
  Groq/Gemini/Ollama code paths are implemented but need a key/server for a live run.
- Mock-provider section text is templated; real LLM output is fully written prose.
